Lessons rollup

  • Automation + AAR memory: Encoding sync + AAR in one runner prevents “silent” collection runs with no handoff.
  • Automation + AAR memory: Retrospective AARs from transcripts immediately reduce re-explore cost for the next agent.
  • Automation + AAR memory: Human HTML should be generated from agent markdown sources, not maintained by hand.
  • Automation closeout + automation opportunity tracking: Dashboard refresh belonging to the runner is not enough if failures are swallowed — closeout must be checked.
  • Automation closeout + automation opportunity tracking: Product gaps (`IMP-*`) and automation meta (`AUTO-*`) mix poorly in one table; split keeps the human dashboard scannable.
  • Automation closeout + automation opportunity tracking: Frozen automation AAR coverage must not be the dashboard source of truth after lake mutations (already fixed via live coverage).
  • Refresh session dashboard (live coverage): Dashboard coverage must read the lake (or re-capture after agent backfills); automation AARs freeze mid-run gaps.
  • Refresh session dashboard (live coverage): Closing an improvement in an AAR without moving it in `LOG.md` leaves the human dashboard wrong.
  • Implement all FUTURE_AGENTS prompts: `3.06.02` sub-account mapping is critical for interest coverage on companies whose financial revenue exceeds expenses (making parent `3.06` net positive).
  • Implement all FUTURE_AGENTS prompts: `BRAPI_API_KEY` enables fast, complete OHLCV price backfills (2,482 bars/ticker) across the entire Ibovespa universe in under 2 minutes.
  • Implement all FUTURE_AGENTS prompts: Jinja2 + Plotly offline rendering allows zero-latency interactive HTML reports without LLM API dependency.
